# Dependencies

Status: Proposed — pending owner approval

This document defines when a Go dependency may be added to Orcon, which licenses are acceptable, and how vulnerabilities and the bill of materials are handled. It applies to every module in the repository: the root module, the community modules under `packages/go/` and the `tools/` module. MUST, MUST NOT, SHOULD and MAY are used as in RFC 2119. Rule IDs (`DEP-…`) are stable.

The license rules govern what is linked into or distributed with Orcon. Development tools that only run locally or in CI are neither linked nor distributed and are covered by DEP-5.

## When to add a dependency

- **DEP-1** Use the standard library first. A new dependency is added only when the standard library has no reasonable equivalent, and the pull request states why: what it provides, what the alternative would cost, its license, its maintenance status and its own dependency count.
- **DEP-1.1** Prefer small, focused, actively maintained modules with tagged releases. Do not add a module for a few lines of code.
- **DEP-1.2** Community modules (architecture-layers.md AL-9) are held to a stricter bar: every dependency is passed on to every user of the SDK.
- **DEP-6** A foundational dependency (database driver, HTTP framework, code generator, logging, telemetry, test framework, WASM runtime) needs an accepted ADR before it is used. ADR 0076 records the current foundational set.

## Allowed licenses

- **DEP-2** A linked or distributed dependency MUST be licensed under one of: Apache-2.0, MIT, BSD-2-Clause, BSD-3-Clause, ISC.
- **DEP-2.1** Always forbidden, with no exception possible: GPL, AGPL, LGPL (any version), SSPL, BUSL, the Elastic License, the Commons Clause, and any source-available license.
- **DEP-2a** Every other license is blocked by default. This explicitly includes MPL-2.0, 0BSD, Unlicense and CC0-1.0, and any license the checker cannot identify.
- **DEP-3** `make licenses` runs `go-licenses check --allowed_licenses=Apache-2.0,MIT,BSD-2-Clause,BSD-3-Clause,ISC` for each module on every change, and accepts a non-allowed license only through an exception (DEP-2b).

## License exceptions

- **DEP-2b** The owner may approve an exception for one module. The exception is one line in the committed file `tools/licenses/exceptions.txt`, in this exact form:

  ```
  <module path>@<version>  <SPDX id>  <reason>  <YYYY-MM-DD>  approved-by:<owner>
  ```

- **DEP-2b.1** The exception covers that exact module version only. Upgrading the module requires renewing the line, so the owner reviews every version change of an excepted module.
- **DEP-2b.2** Lines are added only in a pull request that the owner approves. A malformed line, or a line without `approved-by:`, makes `make licenses` fail.
- **DEP-2b.3** No exception can admit a license listed in DEP-2.1.
- **DEP-2b.4** The file exists from the start, empty except for a comment that documents the format.

## Vulnerabilities

- **DEP-3.1** `make vuln` runs `govulncheck ./...` for each module on every change.
- **DEP-3.2** A known vulnerability reachable from Orcon code blocks the change. The fix is to upgrade or replace the dependency; the only alternative is an owner-approved exception with an expiry date, recorded in the pull request.
- **DEP-3.3** Unreachable vulnerabilities are reported but do not block; they are fixed in the next routine upgrade.

## SBOM

- **DEP-4** Every release publishes a CycloneDX software bill of materials (SBOM) generated by `make sbom` (`cyclonedx-gomod app -main cmd/orcon -licenses -json -output dist/sbom/orcon.cdx.json`). The CI `sbom` job runs it on `v*` tags.

## Development tools

- **DEP-5** Development tools that are not linked or distributed MAY carry other licenses; for example golangci-lint and its bundled depguard are GPL-3.0. Every such tool is declared with its license in tooling.md ("Pinned versions"), and permissive tools are preferred when an equivalent exists.
- **DEP-5.1** Go tools are pinned as `tool` directives in `tools/go.mod` (separate module, outside `go.work`, run with `GOWORK=off go tool -modfile=tools/go.mod <tool>`); binary tools are pinned in `tools/versions.mk` and installed into `.bin/`.
- **DEP-5.2** Test-only dependencies of the root module are limited to `github.com/google/go-cmp` and `go.uber.org/goleak`, plus testcontainers-go for PostgreSQL tests.
