# Expression engine measurement report

Generated by `make expr-report` (`go test ./internal/adapter/wazero -run TestExprMeasurementReport`; see "Reproducing"). Evidence for SPEC-001 criteria E-EXPR-2 and E-EXPR-3 and for the decision of ADR-0018 sections 3 and 4.

**Decision under review:** run non-trivial expressions in QuickJS compiled to WebAssembly on wazero, with a Go fast path for simple expressions (ADR-0018 sections 2 and 3).

**Outcome, with the time limit enforced as ADR-0018 section 3 prescribes (hard limit): REVERSAL CRITERION MET.**

A measured target is missed. This report does not amend the ADR: ADR-0018 section 4 says any change requires amending it, which is the owner's decision.

**Alternative measured, cooperative limit: REVERSAL CRITERION MET.** The deadline is enforced by the QuickJS interrupt handler, polled by the interpreter every ten thousand operations and inside long built-ins (regular expressions, sorting, array methods); the wazero checks are not compiled in. Code that never polls, for example a native string search over megabytes, is bounded by the memory cap only: the test `TestSandboxIsolation` records a crafted `JSON.stringify` of a 100000-deep array that outlives its 150 ms limit by about 2.7 s. This is a deviation from ADR-0018 section 3 and would need an amendment.

## Mode 1: hard limit

The deadline closes the WebAssembly module when the context is done (wazero close-on-context-done), as ADR-0018 section 3 prescribes. wazero compiles a check into every function and loop of the module for this; the QuickJS interpreter loop pays it on every bytecode operation.

## Reading the result

- hard limit: median-complexity expressions without Luxon have a p99 of 177.0 µs (meets the 200µs target); expressions that run Luxon, 831.5 µs (misses).
- cooperative limit: median-complexity expressions without Luxon have a p99 of 46.8 µs (meets the 200µs target); expressions that run Luxon, 234.5 µs (misses).
- Luxon is used by 3.1 % of the code segments of the corpus (2.6 % weighted by views) and by 15.3 % of the segments that need the sandbox. It is a large library that the interpreter runs operation by operation, so a single date operation costs tens to hundreds of microseconds however fast the call into the sandbox is.
- The cost of the time limit is the difference between the modes: wazero's close-on-context-done adds a check to every function and loop of the module, and the interpreter runs several times slower with it. The alternative mode gives the interpreter its full speed and stops runaway code at the next poll of the interrupt handler, but code that never polls is bounded by the memory cap only.
- This report applies the targets as written and does not amend ADR-0018. Whether to keep the prescribed mechanism, adopt the cooperative one, restate the target for date expressions, or give the most common date operations a fast path is the owner's decision.

## Isolation and determinism

These are tests, not measurements: `TestSandboxIsolation` (memory bombs, infinite loops, regular-expression backtracking, runaway recursion, attempts to reach the host, state left behind; run in both modes), `TestSandboxContainsABadNeighbour` (one failing execution among many; both modes) and `TestDeterminism` (recorded time and seeded randomness). They run in `make check`.
