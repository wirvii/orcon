# Expression engine measurement report

Generated by `make expr-report` (`go test ./internal/adapter/wazero -run TestExprMeasurementReport`; see "Reproducing"). Evidence for SPEC-001 criteria E-EXPR-2 and E-EXPR-3 and for the decision of ADR-0018 sections 3 and 4.

**Decision under review:** run non-trivial expressions in QuickJS compiled to WebAssembly on wazero, with a Go fast path for simple expressions (ADR-0018 sections 2 and 3).

**Outcome, with the time limit enforced as ADR-0018 section 3 prescribes (hard limit): REVERSAL CRITERION MET.**

A measured target is missed. This report does not amend the ADR: ADR-0018 section 4 says any change requires amending it, which is the owner's decision.

**Alternative measured, cooperative limit: REVERSAL CRITERION MET.** The deadline is enforced by the QuickJS interrupt handler, polled by the interpreter every ten thousand operations and, in the patched module (QuickJS-ng 0.17.0 plus the interrupt-poll patch), inside the built-ins whose work grows with the input (string search, replace, split, repeat, pad, JSON, join, concat, flat, case conversion, URI encoding) as well as the regular-expression, sorting and array built-ins upstream already polls; the wazero checks are not compiled in. The caller still waits for the code to reach a poll, and code in a built-in the patch does not cover is bounded by the memory cap only (upstream, a crafted `JSON.stringify` of a 100000-deep array outlived a 150 ms limit by about 2.7 s). This is a deviation from ADR-0018 section 3 and would need an amendment; it is not a production mode.

**Alternative measured, cooperative limit with abandon: REVERSAL CRITERION MET.** The cooperative mode of the patched module plus an answer at the deadline: the call runs on its own goroutine and the caller stops waiting when the context is done, whatever the module is doing; the abandoned call stops at its next poll, closes its runtime, and the runtime is never reused. This is the prototype of SPEC-001 amendment 10, A.4; the choice between it and the hard limit is the owner's (B.1).

## Mode 1: hard limit

The deadline closes the WebAssembly module when the context is done (wazero close-on-context-done), as ADR-0018 section 3 prescribes. wazero compiles a check into every function and loop of the module for this; the QuickJS interpreter loop pays it on every bytecode operation.

## Reading the result

- hard limit: median-complexity expressions without Luxon have a p99 of 183.1 µs (meets the 200µs target); expressions that run Luxon, 807.9 µs (misses).
- cooperative limit: median-complexity expressions without Luxon have a p99 of 43.3 µs (meets the 200µs target); expressions that run Luxon, 228.1 µs (misses).
- cooperative limit with abandon: median-complexity expressions without Luxon have a p99 of 84.4 µs (meets the 200µs target); expressions that run Luxon, 348.0 µs (misses).
- Luxon is used by 3.1 % of the code segments of the corpus (2.6 % weighted by views) and by 15.3 % of the segments that need the sandbox. It is a large library that the interpreter runs operation by operation, so a single date operation costs tens to hundreds of microseconds however fast the call into the sandbox is.
- The cost of the time limit is the difference between the modes: wazero's close-on-context-done adds a check to every function and loop of the module, and the interpreter runs several times slower with it.
- A coarser outer deadline saves nothing. The cost is not paid when the deadline is reached; it is the check wazero compiles into every function and loop whenever close-on-context-done is on, and it is paid on every operation whatever the length of the deadline. wazero cannot stop, from outside, a module that was compiled without those checks. The only way to answer exactly at the deadline without them is to stop waiting for the code rather than to stop the code: run the call on its own goroutine and abandon it at the deadline, which is the third mode.
- The cooperative modes stop the code at the next poll of the interrupt handler. Without the patch, code that never polls (a native string search over megabytes, a deep `JSON.stringify`) outlives its deadline by seconds and is bounded by the memory cap only. The patched module polls inside the built-ins whose work grows with the input, so an abandoned call ends within the overshoot table above.
- Only the hard limit is a production mode today. The cooperative modes exist so this report and the tests can measure them; an architecture test keeps them out of every other package, of the configuration and of the flags (SPEC-001 amendment 10, A.1). Choosing one is the owner's decision.
- Compatibility gate: the C5 gate of 95 % excludes only identifiers a later specification defines by name (`$fromAI`, SPEC-006), from a closed list in code; `$env` counts as failing. The launch gate of ADR-0019 section 5 uses the full count, the first row of the compatibility table.
- This report applies the targets as written and does not amend ADR-0018. Whether to keep the prescribed mechanism, adopt the cooperative one, restate the target for date expressions, or give the most common date operations a fast path is the owner's decision.
