# Expression engine measurement report

Generated by `make expr-report` (`go test ./internal/adapter/wazero -run TestExprMeasurementReport`; see "Reproducing"). Evidence for SPEC-001 criteria E-EXPR-2 and E-EXPR-3 and for the decision of ADR-0018 sections 3 and 4.

**Decision under review:** run non-trivial expressions in QuickJS compiled to WebAssembly on wazero, with a Go fast path for simple expressions (ADR-0018 sections 2 and 3).

**Outcome, with the production stop of ADR-0018 section 3 as amended by SPEC-001 amendment 10 (cooperative limit with abandon): CONFIRMED.**

This run is informational: the verdict is taken from a run on the reference machine ORCON-REF-1 (amendment 10, B.5), and this one ran on Apple M2 Max,Darwin arm64.

Every target that can be measured in this cut is met. Scenario S1 of the D20 gate (ADR-0019 section 4) depends on the benchmark harness of cut C16 and is still pending; if it fails because of the sandbox, ADR-0018 section 4 names the fallback (goja in a separate worker process pool, never in the host process).

**Alternative measured, hard limit: REVERSAL CRITERION MET.** Measured for comparison only; not a production mode for expressions. The deadline closes the WebAssembly module when the context is done (wazero close-on-context-done), as ADR-0018 section 3 prescribed before the amendment. wazero compiles a check into every function and loop of the module for this; the QuickJS interpreter loop pays it on every bytecode operation. It stays for the Code node and WASM connectors until their cuts measure their own stop.

**Alternative measured, cooperative limit: CONFIRMED.** Measured for comparison only. The cooperative stop of the production mode without the answer at the deadline: the caller waits for the code to reach a check. Code in a built-in the patch does not cover is bounded by the memory cap only (upstream, a crafted `JSON.stringify` of a 100000-deep array outlived a 150 ms limit by about 2.7 s).

## Mode 1: cooperative limit with abandon

The production stop of expression evaluations (ADR-0018 section 3 as amended by SPEC-001 amendment 10): the QuickJS interrupt handler checks the deadline every ten thousand operations and, in the patched module (QuickJS-ng 0.17.0 plus the interrupt-poll patch), inside the built-ins whose work grows with the input; every call runs on its own goroutine and the caller stops waiting when the context is done, so it gets its timeout within the deadline plus 5 ms whatever the guest is doing. The abandoned call stops at its next check, refuses further requests to the host, closes its runtime, and the runtime is never reused. At most eight abandoned calls may still be running in a process.

### Under load

At most GOMAXPROCS - 1 calls run guest code at once (configurable with `--expr-sandbox-slots`), and an abandoned call keeps its slot until its guest returns, so the process always has a scheduler slot for timers and requests. Waiting for a slot does not use the deadline of the expression; a call that waits longer than the slot-wait limit (1 s by default) fails with `ErrSandboxSaturated`.

## Reading the result

- cooperative limit with abandon: median-complexity expressions without Luxon have a p99 of 72.9 µs (meets the 200µs target); expressions that run Luxon, 348.1 µs (meets the 500µs target).
- hard limit: median-complexity expressions without Luxon have a p99 of 187.1 µs (meets the 200µs target); expressions that run Luxon, 839.2 µs (misses the 500µs target).
- cooperative limit: median-complexity expressions without Luxon have a p99 of 53.5 µs (meets the 200µs target); expressions that run Luxon, 293.0 µs (meets the 500µs target).
- "Runs Luxon" means the analysis of the expression names `DateTime`, `Duration`, `Interval`, `$now`, `$today`, a date extension method (`beginningOf`, `diffTo`, `endOfMonth`, `extract`, `format`, `isDst`, `isInLast`, `isWeekend`, `minus`, `plus`) or `toDateTime` (SPEC-001 amendment 10, B.2). The classifier of this harness uses exactly that list, by name: a call to `format`, `plus` or `minus` on a value that is not a date counts as running Luxon here, which can only move a case into the band with the looser target.
- Luxon is used by 3.4 % of the code segments of the corpus (2.7 % weighted by views) and by 16.8 % of the segments that need the sandbox. It is a large library that the interpreter runs operation by operation, so a single date operation costs tens to hundreds of microseconds however fast the call into the sandbox is.
- The cost of the time limit is the difference between the modes: wazero's close-on-context-done adds a check to every function and loop of the module, and the interpreter runs several times slower with it.
- A coarser outer deadline saves nothing. The cost is not paid when the deadline is reached; it is the check wazero compiles into every function and loop whenever close-on-context-done is on, and it is paid on every operation whatever the length of the deadline. wazero cannot stop, from outside, a module that was compiled without those checks. The only way to answer exactly at the deadline without them is to stop waiting for the code rather than to stop the code: run the call on its own goroutine and abandon it at the deadline, which is the production stop measured first in this report.
- The cooperative modes stop the code at the next poll of the interrupt handler. Without the patch, code that never polls (a native string search over megabytes, a deep `JSON.stringify`) outlives its deadline by seconds and is bounded by the memory cap only. The patched module polls inside the built-ins whose work grows with the input, so an abandoned call ends within the overshoot table above.
- The production stop of expression evaluations is the first mode of this report. The hard limit and the cooperative limit without abandon are measured for comparison and for the tests; the adapter selects the production one by default, and an architecture test (`TestProductionStopMode`) keeps the other two out of every other package, of the configuration and of the flags (SPEC-001 amendment 10, B.1). The hard limit stays for the Code node and WASM connectors until their own cuts measure them.
- Compatibility gate: the C5 gate of 95 % excludes only identifiers a later specification defines by name (`$fromAI`, SPEC-006), from a closed list in code; `$env` counts as failing. The launch gate of ADR-0019 section 5 uses the full count, the first row of the compatibility table.
- The targets are 200 µs without Luxon and 500 µs with it, each the p99 of the median of three runs, measured with the production stop (ADR-0018 section 4 as amended). The verdict is the run on ORCON-REF-1; this report does not amend the reversal criterion, which is unchanged.
