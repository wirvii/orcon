# ADR 0080: Public API design rules and contract toolchain

Status: Accepted | Amended: 2026-10-13 (SPEC-012 Amendment 2); amended 2026-10-13 (SPEC-016)

## Context
ADR-0052 to ADR-0059 define one public REST API described by OpenAPI 3.1, used by the editor, the CLI, the SDKs and the MCP server. They fix conventions (pagination, problem+json, idempotency, ETags, rate classes, long-running operations, events, versioning) but leave open how paths are named, which action verbs exist, how enum values are written, how every channel declares its exposure, what an operation must document, and which tools enforce all of it. The maintainers fixed binding direction: plural kebab-case resources nested at most one level, a closed action-verb list, UPPER_SNAKE enum values matching the engine, every operation declaring its CLI command (or a written reason) and its MCP exposure level, complete documentation with examples executed against the real binary, a browsable reference with a try-it feature served by every binary, a per-release API changelog, and responses without envelopes.

## Decision
1. Rules. The rules live in the repository skill `orcon-api` (`.agents/skills/orcon-api/references/`); `docs/engineering/api.md` summarizes them. Code generation and handler rules stay in the `orcon-go` skill (`api-codegen.md`).
2. Paths (amends ADR-0052 §2 and §3). Grammar: collection, item, singleton, view, action, stream, with at most two path parameters and one parent level; namespaces `instance`, `catalog`, `users/me`; protocol-tagged operations are outside the grammar. Non-CRUD actions are `POST <item or singleton>/<verb>` with one of thirty-one verbs: activate, deactivate, enable, disable, pause, resume, publish, rollback, move, cancel, retry, continue, repeat, acknowledge, resolve, complete, signal, approve, reject, rotate, revoke, test, validate, evaluate, export, sync, redeliver, replay, upgrade, authorize, reindex. Renames: `flows/{flowId}/draft/expression-preview` becomes `flows/{flowId}/draft/evaluate`; `credentials/{credentialId}/oauth/authorize` becomes `credentials/{credentialId}/authorize`. Listing by a non-owner relation uses filters, never extra nesting.
3. Enum values (amends ADR-0052, ADR-0053, ADR-0055, ADR-0056, ADR-0059 and ADR-0073). Every enum and state value that crosses a public interface is UPPER_SNAKE. This includes documents the API returns verbatim and whose schemas the contract references, such as `orcon/flow@1` flow documents and connector manifests; the designs that own those formats apply it to them. Identifier catalogs (event types, permission names, problem codes, operation ids, MCP tool names, media types, values fixed by external standards) are not enums of state and keep their own form, marked `x-orcon-enum-kind: identifier`. Values of `x-orcon-*` extensions are contract metadata, not API data, and keep the form defined in the skill.
4. Extensions (amends ADR-0054 §1 and ADR-0059 §2). The full set and shapes are listed in the skill (`extensions.md`). New: `x-orcon-resource`, `x-orcon-problems`, `x-orcon-examples`, `x-orcon-long-running`, `x-orcon-event`, `x-orcon-sort-default`, `x-orcon-enum-kind`, `x-orcon-volatile`, `x-orcon-deprecation-guide`. `x-orcon-mcp` becomes `{ level: none | read | write | destructive, tool?, description? }`; confirmation is derived from `destructive`; the key `confirm` no longer exists. `x-orcon-permission` accepts a permission, `{ allOf }`, `{ anyOf }`, `authenticated`, or `anonymous` (protocol operations, and the closed list of non-protocol operations that must work before any credential exists: `createSession`, `getSetupState`, `createSetupSession`; adding one amends this list).
5. CLI coverage (amends ADR-0058 §3). Every stable or beta operation declares `x-orcon-cli.command` or `x-orcon-cli.none` with a category from `protocol`, `ingress`, `interactive-session-only` and a reason.
6. Events. Public event types are described in the OpenAPI `webhooks` section, one entry per type, with `x-orcon-event`, so they share the lint, the reference and the changelog.
7. Responses. No envelopes: a resource is returned as itself, a list as `{ items, nextPageToken? }`, an error as problem+json, and auxiliary data in headers (`Orcon-Request-Id`, `ETag`, `RateLimit`, `RateLimit-Policy`, `Location`, `Deprecation`, `Sunset`).
8. Documentation. Every operation has a summary, a description of what and when, a permission, every possible problem code and at least one success example; every field has a description and, where applicable, a format, allowed values and an example. Permission, rate class, stability, problems, CLI command and MCP tool are rendered from the extensions, never written by hand. Examples are executed against the real binary in tests: on SQLite for every pull request and on PostgreSQL every night.
9. Toolchain (CI only unless stated). Redocly CLI (MIT) bundles and lints the contract with a project plugin; oasdiff (Apache-2.0) checks compatibility against the latest released contract and writes the per-release API changelog; Scalar API Reference (MIT) renders the reference with a try-it feature from a vendored script and is shipped as a static asset; `github.com/santhosh-tekuri/jsonschema` (Apache-2.0) validates real responses in tests only.
10. Reference site (amends ADR-0052 §1). The `api` and `standalone` roles serve the reference at `/api/reference`, same origin as the API, so try-it works offline and without cross-origin configuration. Try-it sends only a bearer credential typed by the user, never cookies; the page loads no external resource and is served with the content security policy `default-src 'self'; connect-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data:; base-uri 'self'; form-action 'none'; frame-ancestors 'none'; object-src 'none'`. Inline styles are allowed because the reference renderer injects its styles at run time; inline scripts and `eval` stay blocked. `GET` and `HEAD` on `/api/reference` answer `301 Moved Permanently` with `Location: /api/reference/` (query string kept), because the site resolves its files relative to that path. The site adds at most 3 MiB compressed to the binary; it is also attached to every release.
11. Checks run outside `make check` in their own make targets and CI jobs.

## Consequences
Every contract change is reviewed against one machine-checked rule set before a person reads it. Clients see one response shape everywhere, and the same value spelling in operations and in the documents they return. The CLI and MCP surfaces cannot drift silently from the contract. Documentation cannot claim behavior the server does not have. Every installation carries the reference for exactly the API it serves. Enum values and two routes change in documents that are still proposed; nothing published breaks. The repository gains a Node tool package, a shipped static asset and a test-only Go dependency; a PostgreSQL-only example failure is found on the next nightly run.

## Alternatives considered
Spectral (Apache-2.0) as linter (needs a separate bundler). Redoc as reference (no try-it in the free edition). Swagger UI (Apache-2.0; viable, weaker OpenAPI 3.1 rendering). A separately hosted static reference only (try-it would need cross-origin access on every instance). Running examples on both databases for every pull request (doubles the required job time). Response envelopes with `data` and `meta` (rejected by the maintainers; duplicate information that headers already carry). Free-form action names. Lowercase enum values (differ from the engine states). Excluding documents returned verbatim from the enum rule (the same value would be spelled two ways across one response). Examples checked only against schemas (a valid but wrong example would pass).

## Amendments
Changes applied after acceptance; each entry names its source.

- **SPEC-012 (Amendment 2, 2026-10-13, owner decision).** §10: the content security policy of the reference site adds `style-src 'self' 'unsafe-inline'`, `img-src 'self' data:`, `base-uri 'self'`, `form-action 'none'`, `frame-ancestors 'none'` and `object-src 'none'` (measured: the renderer injects its styles at run time and is unusable without inline styles), and `/api/reference` redirects to `/api/reference/`. §9: the Redocly built-in rule `operation-4xx-problem-details-rfc7807` is turned off for the real contract, because protocol-tagged operations answer errors in the format of their external standard; the project rule `orcon/problem-responses` requires problem+json for every other operation (ERR-1). A secret Orcon generates is returned exactly once, in `<Resource>WithSecret` (FIELD-7); a resource reports how it failed in `failure`, never `error` (RESP-6); the evaluate response member is `itemResults` (ADR-0052 §7).
- **SPEC-016 (2026-10-13).** §4: `anonymous` is also allowed on a closed list of non-protocol operations (password sign-in and the first-run setup entry points); owner decision.
