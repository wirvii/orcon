# ADR 0079: Connector authoring conventions and toolchain

Status: Accepted

## Context
ADR-0029 to ADR-0037 define what a connector is (manifest, kinds, safety contract, egress, trust, versioning, conversion and coverage). Matching the n8n catalog needs hundreds of connectors, written by Orcon maintainers and by third parties, and they must look and behave the same. The maintainers fixed binding direction: declarative connectors by default, native Go only with a written justification naming the declarative-format gap; n8n's resource and operation model with singular resources and a closed verb vocabulary; uniform pagination, dates, identifiers and error classification; English and Spanish catalogs; recorded real responses replayed offline with automatic scrubbing and a secret and personal-data gate; the common conformance suite; fault tests proving that retries happen only when safe and that ambiguous outcomes become UNCERTAIN; nightly live tests that open a "service changed" issue and never block merges; per-connector semantic versioning checked against an automatic manifest diff; one generated documentation page per connector with a hand-written connection guide. Some of these choices extend or amend ADR-0029, ADR-0030 and ADR-0034 and the layout of ADR-0075. ADR-0029 §10 and ADR-0080 §3 fix that every public enumerated value is UPPER_SNAKE.

## Decision
1. Location. Every official connector, declarative or native, lives in `internal/adapter/connectors/<name>/` with one folder layout: `orcon-package.json`, `connector.json` (declarative) or Go sources (native), `embed.go` (declarative), `i18n/{en,es}.json`, `icons/icon.svg`, `docs/connection-guide.{en,es}.md`, `docs/n8n-equivalence.{en,es}.md`, `authoring.json`, `changes/<from>..<to>.json`, `tests/*.json`, `tests/live.json`, `connector_test.go`. Declarative connectors are embedded with `embed.FS` and registered in `cmd/orcon` like native ones.
2. Package additions (amends ADR-0029 §2 and §4). Packages carry `i18n/en.json` and `i18n/es.json` keyed by stable paths (`node.<node>.displayName`, `operation.<resource>.<operation>.description`, `parameter.<node>.<path>.description`, and so on); the manifest keeps the English text as the default. `changelog` is `[{ version, date, notes: [messageKey] }]` with one entry per released version. `authoring.json` (`orcon/connector-authoring@1`) records the kind justification, verb exceptions and reasons for raw credential access or non-HTTPS networking; it ships in the package for catalog review. Its enumerated values follow §14.
3. Recorded tests (amends ADR-0030 §10). `tests/*.json` use `orcon/cassette@1`: several interactions, an expected result, an `example` flag and scrubber metadata. Recording, replay and request matching are implemented with the Go standard library in the shipped binary, so third-party authors use the same tool. Cassettes are internal test artifacts and keep their recorded values as they are (ADR-0029 §10).
4. Ambiguous outcomes (amends ADR-0030 §5; refines ADR-0011 §1 for writes). `response.errors[].class` accepts `UNCERTAIN`, only on operations whose purity is `EFFECT`. For a write without an idempotency key (`RECONCILE` or `UNSAFE`), a 5xx response, a timeout or a connection failure after the request was sent is an ambiguous outcome: `RECONCILE` asks the provider before deciding, `UNSAFE` becomes UNCERTAIN and asks a person, and neither is resent blindly. A 429 response means the request was not applied and is `TRANSIENT` for every level. Decided by the maintainers on 2026-10-12.
5. Error codes. Connectors classify provider failures with a closed list of fourteen codes (`AuthInvalid`, `AuthExpired`, `PermissionDenied`, `NotFound`, `Conflict`, `ValidationFailed`, `RateLimited`, `QuotaExceeded`, `PayloadTooLarge`, `ServiceUnavailable`, `Timeout`, `NetworkError`, `Unsupported`, `ProviderError`). Error codes are identifiers and keep their form. Host-raised codes such as `EgressDenied` and `ConnectorRevoked` stay with the host.
6. Semantic versioning (amends ADR-0034 §4 and §5). Patch: no difference in the manifest or schemas. Minor: additions only (node, operation, optional parameter, credential type, output port, option value, wider permissions). Major: any removal or rename, a type change, a new required parameter without default, a narrower accepted value set, or a weaker safety level. `orcon connector diff --classify` reports `PATCH`, `MINOR` or `MAJOR`; `--verify-bump` rejects a release whose declared bump differs from the detected one in either direction. Change descriptors gain `addNode`, `addOperation` and `addCredentialType`. Every version has a changelog entry in English and Spanish. Catalogs keep old versions (ADR-0034 §6 governs retirement).
7. Authoring toolchain. `orcon connector` gains `lint [--admission]`, `record`, `scrub`, `docs [--check]`, `diff --classify|--verify-bump` and `test --faults`, next to the commands of ADR-0029 to ADR-0035. The same checks run in Orcon CI and in the automated stage of catalog review (ADR-0033 §9).
8. Test harness adapter. Cassette recording and replay, scrubbing, secret and personal-data detection, fault injection and live runs live in the adapter `internal/adapter/connectortest`. It is a declared exception to adapter privacy, approved by the maintainers on 2026-10-12 and written into the Go architecture rules next to the existing `storetest` exception: it may be imported only by `_test.go` files under `internal/adapter/connectors/**` and by `internal/adapter/cli`. The exception covers this package only.
9. Declarative gaps. `docs/reference/declarative-gaps.md` registers the gaps that justify native connectors (non-HTTP protocols, special request signing, streaming and persistent connections, complex binary formats, multi-step stateful protocols, client-side payload computation). Every official native connector cites one. When a gap is cited by three official native connectors, a fourth one is accepted only with an open backlog item to extend the declarative format for that gap.
10. Live tests. A nightly workflow runs connectors against free provider test accounts when available, compares response shapes with the recorded examples, and opens or updates a "Service changed" issue on failure. It never runs for pull requests and is never a required check. Credentials are environment secrets of the repository, owned by the project, least-privilege and rotated every 90 days.
11. Tools. Shipped tooling is Apache-2.0 code with no new dependency. CI uses the gitleaks command-line tool (MIT) as an independent secret scan of recorded tests and the GitHub CLI (MIT) for issue automation; neither is shipped.
12. The rules that apply these decisions live in the repository skill `orcon-connector` (`.agents/skills/orcon-connector/references/`); `docs/engineering/connectors.md` summarizes them for Orcon and third-party authors.
13. Documentation pages of connectors for AI model providers are generated under `docs/reference/connectors/ai/`, a path the maintainers approved on 2026-10-12 for naming those providers; their code stays under the AI paths already approved. The general index links to that folder without naming providers.
14. Value casing (applies ADR-0029 §10 and ADR-0080 §3). Every enumerated or state value an author writes is UPPER_SNAKE: in the manifest (kinds `DECLARATIVE`, `NATIVE`, `WASM`; node groups; parameter types such as `DATE_TIME` and `RESOURCE_LOCATOR` and their modes `LIST`, `ID`, `URL`; purity `READ`, `EFFECT`; safety levels `READ_ONLY`, `IDEMPOTENCY_KEY`, `RECONCILE`, `UNSAFE` and their sub-values; `proofLevel` `DECLARED`, `TESTED`, `VERIFIED`), in the declarative body (error classes `TRANSIENT`, `PERMANENT`, `UNCERTAIN`; pagination and rate-limit values such as `STREAM`, `TRUNCATE`, `CREDENTIAL`), in `authoring.json` (`kind.chosen`), in `tests/live.json`, in the output of `orcon connector diff --classify`, and in catalog seals (`OFFICIAL`, `VERIFIED`, `UNREVIEWED`). Exempt, as in ADR-0029 §10: recorded tests in `orcon/cassette@1`; identifiers (node types and names, resources, operations and verbs, error codes, credential type ids, change-descriptor operations, TUF role and delegation names); values fixed by external standards (HTTP methods, URL schemes, algorithm names); and option values a connector defines for its own parameters, which are connector data (ADR-0030 §3). Manifest schema validation rejects any other spelling.

## Consequences
Connectors are reviewed against one checklist that a machine enforces before a person reads them. Third-party authors get the same tools as maintainers. Recorded tests run offline on every change; drift in real services is detected nightly without blocking contributors. Versioning is honest by construction, and users see what changes before upgrading. Unstable services can suspend more executions waiting for a person instead of risking duplicate writes. A value reads the same in a manifest, the API and the database. The toolchain adds code to the binary and one narrowly scoped adapter exception; the declarative format grows when the same gap recurs instead of accumulating native code.

## Alternatives considered
go-vcr (BSD-2-Clause; its own YAML format, generic matching that cannot ignore host-applied values, and a new dependency in the shipped binary). TruffleHog (AGPL-3.0; excluded by the license policy). The gitleaks GitHub Action from v2 (commercial license). A separate authoring binary (two tools for authors to install and keep in sync). Declarative connectors in a top-level `connectors/` folder (outside the Go layout of ADR-0075; still needs embedding). Normalizing provider dates in outputs (breaks imported n8n expressions). Free-form verbs (inconsistent operation names and harder n8n mapping). Live tests as a required check (provider outages would block unrelated work). Treating a 5xx on a write as a definite failure (a write applied before the error could be repeated by hand and duplicated without warning). Generating AI-provider pages next to their code only (users would not find them with the rest of the connector documentation). Lowercase or camelCase values in author-written formats (rejected by ADR-0029 §10 and ADR-0080 §3: one spelling for every public value).
