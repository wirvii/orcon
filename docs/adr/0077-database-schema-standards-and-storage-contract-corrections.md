# ADR 0077: Database schema standards and storage contract corrections

Status: Accepted | Amended: 2026-10-13 (required timestamp columns clarified)

## Context
ADR-0015 defines the storage contract (type mapping, logical schema, migrations) and ADR-0046/0047 define multi-organization isolation. ADR-0075 and ADR-0076 (accepted) fix the module layout and the SQL toolchain (sqlc with separate SQLite and PostgreSQL query sets), and the accepted Go rulebook (`.agents/skills/orcon-go/references/data-access.md`, rules DA-1 to DA-8) governs how Go code reaches the database. The maintainers fixed binding database standards: singular snake_case names without abbreviations, `id` primary keys holding application-generated UUIDv7 values, `<table>_id` foreign keys, `org_id` on every organization-scoped row, actor columns that reference a principal, forward-only paired migrations, constraints enforced by the database, JSON only for whole documents, soft delete only for flows, bounded indexed queries. Checked against these standards, the ADR-0015 logical schema lacks `org_id` on 28 organization-scoped tables, lacks `id` on many, and uses plural, abbreviated and reserved names. Some mappings cannot be enforced as written (SQLite `BLOB(16)` in STRICT tables, `INTEGER PRIMARY KEY` sequences), PostgreSQL 14 views bypass row-level security, and lookups that happen before the organization is known are missing from the engine-plane function list.

## Decision
1. The rules in `.agents/skills/orcon-db/references/` (the database rulebook) are the schema, migration and query standard for both stores. They detail, and never contradict, the accepted rules DA-1 to DA-8. Automated checks: `tools/dbcheck` (static) and `internal/adapter/storetest/dbrules` (catalog introspection, connection settings, query plans, upgrades from a seeded previous version) on SQLite and PostgreSQL 14 and 17.
2. Amends ADR-0015 §2 (type mapping):
   - ID: PostgreSQL `uuid`; SQLite `BLOB` in a `STRICT` table with `CHECK (length(id) = 16)`; RFC 9562 byte order. Generated by the application only.
   - Timestamp: PostgreSQL `timestamptz` (session time zone UTC); SQLite `INTEGER` unix microseconds UTC.
   - JSON document: PostgreSQL `bytea` by default, `jsonb` only for a column with an approved JSON-path exception; SQLite `BLOB`. Every document column has a sibling `<name>_document_format` tag (`orcon/<kind>@<major>`).
   - Bool: PostgreSQL `boolean`; SQLite `INTEGER` with `CHECK (x IN (0, 1))`.
   - Sequence numbers are non-key `sequence_number` columns (PostgreSQL `bigint`, SQLite `INTEGER` assigned by the single writer) with a UNIQUE constraint; never row identity.
   - Every SQLite table is `STRICT`. PostgreSQL ENUM types, domains, arrays, `varchar(n)`, `timestamp` without time zone, `date`, `time`, `interval`, `money`, floating point and serial types are not used.
3. Amends ADR-0015 §3 (logical schema). Every table has `id` (PK), `created_at`, and `updated_at` unless append-only; organization-scoped tables have `org_id` NOT NULL, composite foreign keys `(org_id, <parent>_id) REFERENCES <parent>(org_id, id)`, and `UNIQUE (org_id, id)` when referenced. JSON columns are `<name>_document` with `<name>_document_format`. Actor columns are `<verb>_by_principal_id` (decision 8). Columns abbreviated with "…" are completed by the implementing slice under the rulebook.
   - Instance tables: `schema_migration(version PK, checksum, applied_at, binary_version, compatibility_floor)` (sole exception to the `id` rule); `worker(id, role, host, version, started_at, heartbeat_at)`; `org(id, name, status, …)` (isolated by its own id); `principal(id, kind, created_at)` with `kind` in `USER`, `SERVICE_ACCOUNT`, `SYSTEM` (the spelling the API exposes, decision 11) and exactly one `SYSTEM` row per installation; `instance_alert(id, kind, subject_reference, status, level, summary, affected_reference_document, acknowledged_by_principal_id, acknowledged_at, next_escalation_at, closed_at, closed_reason)`.
   - `project(org_id, id, name, slug, environment, is_protected)`.
   - `flow(org_id, id, project_id, name, draft_document, draft_revision, active_flow_version_id, deleted_at, deleted_by_principal_id)`; name unique per project among non-deleted flows.
   - `flow_version(org_id, id, flow_id, version_number, document, content_hash, warning_document, published_by_principal_id, published_at)` append-only; unique `(org_id, flow_id, version_number)`.
   - `flow_snapshot(org_id, id, flow_id, content_hash, document)` append-only; unique `(org_id, content_hash)`.
   - `call_edge(org_id, id, flow_version_id, target_flow_id, kind, is_intentional, maximum_depth)` append-only.
   - `execution(org_id, id, project_id, flow_id, flow_version_id, flow_snapshot_id, status, mode, priority, parent_execution_id, parent_token_id, root_execution_id, call_depth, call_chain_document, retried_execution_id, run_generation, cancel_requested_at, undo_requested_at, runnable_count, leased_count, waiting_count, suspended_count, active_milliseconds, throttle_kind, error_document, summary_document, data_key_wrapped, started_at, finished_at)`; exactly one of `flow_version_id`, `flow_snapshot_id`.
   - `token(org_id, id, execution_id, status, node_id, edge_id, scope_path, fork_lineage, payload_reference, fairness_key, effective_priority, available_at, lease_owner, lease_epoch, lease_expires_at, claim_count, abandoned_count, deferred_until_at, suspend_reason)`.
   - `node_execution(org_id, id, execution_id, token_id, node_id, scope_path, status, attempt_count, item_state_document, item_route_document, output_reference_document, error_document, started_at, finished_at)`.
   - `task_attempt(org_id, id, execution_id, node_execution_id, attempt_number, lease_epoch, worker_id, status, item_document, error_document, started_at, finished_at)`.
   - `node_output(org_id, id, execution_id, node_execution_id, port, item_count, encoding, inline_document, blob_id)`.
   - `external_operation(org_id, id, execution_id, node_execution_id, item_index, correlation_key, contract_reference, state, batch_key, request_reference, response_reference, dispatch_deadline_at, first_dispatched_at, retry_epoch, compensation_state, resolved_by_principal_id, evidence_reference)`; unique `(org_id, correlation_key)`.
   - `join_instance(org_id, id, execution_id, node_id, scope_path, edge_state_document, status, continuation_token_id)`; `join_arrival(org_id, id, execution_id, node_id, scope_path, edge_index, token_id, payload_reference, is_live, arrived_at)`; `merge_tracker(org_id, id, …)`; `multi_instance(org_id, id, execution_id, node_id, scope_path, total, started, completed, in_flight, status)`.
   - `timer(org_id, id, execution_id, token_id, kind, due_at, status, payload_document)`; `wait(org_id, id, execution_id, token_id, node_execution_id, kind, wait_group_key, secret_hash, expires_at, status, resume_payload_reference)`; `human_task(org_id, id, …)`.
   - `variable(org_id, id, execution_id, scope_path, name, value_document, version)`; `variable_change(org_id, id, sequence_number, execution_id, scope_path, name, node_execution_id, changed_at, old_value_reference, new_value_reference)` append-only.
   - `flow_data(org_id, id, flow_id, data_key, value_document, version)`; `flow_data_operation(org_id, id, operation_key, result_document, applied_at)`.
   - `nondeterminism_record(org_id, id, execution_id, node_execution_id, sequence_number, value_document)` append-only.
   - `execution_event(org_id, id, execution_id, root_execution_id, sequence_number, occurred_at, type, schema_version, reference_document, data_document)` append-only; unique `(org_id, execution_id, sequence_number)`; `sequence_number` orders the events of one execution and is not the primary key.
   - `outbox(org_id, id, topic, payload_document, lease_owner, lease_expires_at, delivered_at, attempt_count)`.
   - `blob(org_id, id, execution_id, flow_id, size_bytes, sha256, media_type, backend, location, committed_at)`; `blob_chunk(org_id, id, blob_id, chunk_index, data)`.
   - `limit_bucket(org_id, id, bucket_key, capacity, refill_per_second, tokens, blocked_until_at)`; `trigger_rate(org_id, id, flow_id, window_started_at, fire_count)`.
   - `attention_request(org_id, id, execution_id, project_id, flow_id, flow_version_id, node_id, token_id, cause, cause_reference, notify_class, status, level, group_key, item_count, summary, acknowledged_by_principal_id, acknowledged_at, next_reminder_at, next_escalation_at, resolved_at, resolved_by_principal_id, resolution, action)`; unique `(org_id, cause_reference)`.
   - `attention_routing(org_id, id, scope_kind, project_id, flow_id, cause, recipient_document, escalation_document, reminder_document, coalesce_window_milliseconds, overdue_after_milliseconds, revision)`.
   - `notification(org_id, id, application_user_id, attention_request_id, group_key, kind, read_at)`; `notification_delivery(org_id, id, deduplication_key, channel, recipient, status, attempt_count, next_attempt_at, last_error, finished_at)` unique `(org_id, deduplication_key)`; `notification_group(org_id, id, group_key, channel, window_ends_at, pending_count)`.
   - `operational_alert(org_id, id, kind, subject_reference, status, level, summary, affected_reference_document, acknowledged_by_principal_id, acknowledged_at, next_escalation_at, closed_at, closed_reason)` with `org_id` NOT NULL; instance-level alerts use `instance_alert`.
4. Soft delete exists only on `flow` (`deleted_at`, `deleted_by_principal_id`). A deleted flow can be restored for 30 days (audit events `flow.deleted`, `flow.restored`). After 30 days retention deletes it physically in bounded batches (its executions first, then versions, snapshots and call edges, then the flow row) and records `flow.purged` in the transaction that deletes the flow row; a flow with an unfinished execution is purged on a later run. Every other deletion is a hard delete recorded in the audit log.
5. Other designs follow the same rules: organization-scoped tables of the trigger, connector grant, identity link, AI stream and MCP snapshot designs gain `org_id`; tables with an optional `org_id` are split into organization and instance tables (key canaries, audit chains); `user_id` columns become `application_user_id`; abbreviated names are spelled out (decision 7); `jsonb` columns and in-JSON queries become `bytea`/`BLOB` documents with real columns, unless an owner-approved exception exists (decision 9).
6. Amends ADR-0046: the instance-table list lives in `internal/adapter/storetest/dbrules/policy/instance_tables.txt`; the query scope annotation is a separate line `-- orcon:scope org|instance|engine`; no views on organization data (PostgreSQL 14 views run with owner privileges and bypass row-level security); the first PostgreSQL migration revokes `CREATE` on schema `public` from `PUBLIC`; the `org` table is isolated by its own `id`; names without abbreviations: context schema `orcon_context` (was `orcon_ctx`), runtime role `orcon_application` (was `orcon_app`), function `orcon_context.current_org_ids()` (was `current_orgs()`), table `application_user` (was `app_user`). Amends ADR-0047 §2: lookups that run before the organization is known are engine-plane functions returning `org_id`: `resolve_trigger_address`, `resolve_api_key`, `resolve_oauth_token`, `resolve_wait_secret`, `resolve_public_entry`.
7. Names contain no abbreviations except `id`, `org` and the acronyms listed with their expansion in `internal/adapter/storetest/dbrules/policy/allowed_acronyms.txt`; `policy/abbreviation_denylist.txt` is the checked definition of an abbreviation. Both checkers read these two files. Adding an acronym requires owner approval.
8. Actor columns reference `principal`: a user, a service account or the system acts through one `principal` row; `application_user` and `service_account` reference it through a unique `principal_id`. Every column that records who did something is `<verb>_by_principal_id`, nullable, with a single-column foreign key to `principal(id)` `ON DELETE SET NULL` and a supporting index. Deleting a principal therefore never deletes history; the audit log keeps the actor's identity in `actor_principal_id` without a foreign key, plus its kind and the keyed hash defined by ADR-0048.
9. JSON in SQL: no query reads inside a JSON document without a written, owner-approved exception; documents are `bytea` (PostgreSQL) or `BLOB` (SQLite) by default and `jsonb` is used only for a column with such an exception. The Go rulebook rule DA-3 (`data-access.md`) was amended by the maintainers on 2026-10-12 to state the same, so both rulebooks agree.
10. Migration files carry a header (`-- orcon:kind`, `-- orcon:compatibility-floor`, `-- orcon:contracts`, `-- orcon:no-transaction`) that the ADR-0015 §4 runner reads to record the compatibility floor; checksums are SHA-256 of the LF-normalized file, the same value recorded in `migrations.sum` and in `schema_migration.checksum`.
11. Value spelling. Every enum and state value that crosses a public interface (API requests and responses, event payloads, and documents the API returns verbatim such as `orcon/flow@1` flow documents and connector manifests) is UPPER_SNAKE, as ADR-0080 §3 states for the API. Documents stored whole and returned verbatim therefore hold UPPER_SNAKE values. `principal.kind` stores the spelling the API exposes (`USER`, `SERVICE_ACCOUNT`, `SYSTEM`). The storage spelling of other enumerated columns is fixed by the design that owns the table; whatever spelling is stored, its CHECK lists it exactly.

## Consequences
Every row carries its organization, so row-level security and the static scope check apply uniformly; constraints catch invalid writes on both stores; schema changes are mechanically checked before merge. Names get longer where abbreviations were used, and one schema, one role and one function of the isolation design are renamed. Every actor column adds an index. Only flows can be recovered after deletion. Data that must be filtered lives in real columns rather than inside JSON on both stores. Events of one execution have a stable order independent of clock resolution. A value is spelled the same way in the API and in the documents it returns. Designs that referenced the old names are updated in a consistency pass before implementation.

## Alternatives considered
Keeping natural primary keys on high-volume tables (rejected: contradicts the `id` rule and complicates composite foreign keys). Nullable `org_id` for instance-level rows (rejected: breaks NOT NULL scoping and row-level security). Actor columns without foreign keys (rejected: loses integrity; the audit log already keeps the identity). Soft delete on projects as well (rejected: project deletion is deliberate and strongly confirmed). Allowing common short forms such as `max`, `min`, `seq`, `ref`, `ms` (rejected by the maintainers). Querying inside JSON with SQLite JSON1 functions and native PostgreSQL `jsonb` (rejected: data filtered inside JSON escapes foreign keys, CHECK constraints and ordinary indexes, and the two dialects diverge). A generic SQL linter (rejected: no tool covers both dialects, row-level security and these policy lists; the in-repo checkers are small and dependency-free). PostgreSQL ENUM types (rejected: no SQLite equivalent, hard to evolve). Ordering execution events by `occurred_at` alone (rejected: equal timestamps have no defined order).

## Amendments
Changes applied after acceptance; each entry names its source.

- **SPEC-009 D4 (2026-10-13, owner decision).** §3: the per-table column lists name each table's own columns. `created_at`, and `updated_at` unless the table is append-only, apply to every table, including `worker`, `principal` and `schema_migration`; `schema_migration` is append-only and exempt only from the `id` rule, and the migration runner writes its `created_at` with the same instant as `applied_at`.
