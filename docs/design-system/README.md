# Orcon design system

The Orcon design system is the shared set of design tokens, themed components, canvas visual language, content and i18n rules, and accessibility requirements that every Orcon web UI surface follows. It covers the embedded editor in `apps/web` and the shared packages under `packages/js` (`@orcon/tokens`, `@orcon/ui`, `@orcon/lint-config`).

The complete, normative rules live in the repository skill `orcon-ui`, which is self-contained and portable. Contributors building or reviewing UI load the `orcon-ui` skill and follow its steps and checks. This page is a human-facing summary only: it does not restate rules, values or token tables, so there is exactly one place to change them.

## Viewing the components

Run Storybook for the component package:

```sh
pnpm --filter @orcon/ui storybook
```

Storybook offers theme (light, dark), density (comfortable, compact), locale (English, Spanish, pseudo-locale) and viewport (mobile, tablet, desktop) controls.

## Brand assets

The brand mark and the mascot are shown as neutral placeholders (an empty outlined frame and the name "Orcon" set in the UI font). The production symbol, wordmark, favicon and mascot exports are delivered in a separate backlog item and replace the placeholders after they are approved against the reference boards in `brand/reference/`. The `BrandMark` and `Mascot` component contracts stay the same when that happens.

## Rule status

All normative references are `Proposed — pending owner approval`. They become `Accepted` only after every row in the table below is `Approved` by the owner. Until then, product screens must not rely on the design system as an accepted source (see [`docs/engineering/implementation-contract.md`](../engineering/implementation-contract.md)).

## Editor parity review

The V1 bar for the flow editor is that every interaction of the parity table in [`canvas.md#parity`](../../.agents/skills/orcon-ui/references/canvas.md#parity) is equal to or better than the n8n editor experience, observed as a user (nothing is copied). The owner records `Equal`, `Better` or `Worse — changes requested` for each row, with the date and the commit of the Storybook reviewed. No row may stay `Worse` when the canvas, editor and S3 rows above are approved. Rows whose owner is SPEC-014 are reviewed when that specification delivers them. The decision mockup of style A is kept at [`mockups/editor-style-a.html`](mockups/editor-style-a.html) as a record; `canvas.md` governs.
